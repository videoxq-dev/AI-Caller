# DeployOS: expose the existing Realtime gateway through Traefik v3

The working AI Caller deployment contains `aicaller-web-1`,
`aicaller-gateway-1`, `aicaller-postgres-1` and `traefik-edge`.
The existing public website router is generated by DeployOS in
`/opt/deployos/traefik/dynamic/generated/aicaller.yml` and points to
`http://aicaller-web:8080`. **Do not replace this router or run a second
Compose project/PostgreSQL database.**

## Network setup (persistent)

The default `docker-compose.yml` attaches `gateway` to both its
private `aicaller_default` network (DB access) and external `edge`
(Traefik ingress). The `edge` network is managed by DeployOS and MUST
already exist. The gateway gets DNS alias `aicaller-voice-gateway`
**on edge only**. `postgres` stays private.

A one-off `docker network connect edge aicaller-gateway-1` can test
connectivity, but is lost when DeployOS recreates that container.
Deploy the PR with the persistent Compose change before relying on the
alias. Do not manually change the bundled database's volume, project
or hostname.

## DNS and Traefik route

Create DNS A record `voice.adacertifyexperts.com` resolving to the
same DeployOS public server as `adacertifyexperts.com`. Verify it
has propagated. Do not change the website's existing A record.

DeployOS's Traefik configuration (observed on this installation):
- Container: `traefik-edge`
- File-provider directory: host
  `/opt/deployos/traefik/dynamic/generated` -> container `/dynamic`
- Entry point: `websecure`
- ACME cert resolver: `letsencrypt`

Create a **separate** route file, not an edit to generated
`aicaller.yml`:

```sh
cat > /opt/deployos/traefik/dynamic/generated/aicaller-voice.yml <<'YAML'
http:
  routers:
    aicaller-voice:
      rule: 'Host(`voice.adacertifyexperts.com`)'
      entryPoints: [websecure]
      tls:
        certResolver: letsencrypt
      service: aicaller-voice
  services:
    aicaller-voice:
      loadBalancer:
        passHostHeader: true
        servers:
          - url: http://aicaller-voice-gateway:3002
YAML
```

Traefik forwards ordinary HTTPS health requests and WebSocket Upgrade
requests through this HTTP service. Raw gateway port 3002 must NOT be
exposed directly to the Internet. The Realtime media WebSocket
authenticates each session using a signed, expiring URL.

IMPORTANT: This directory is DeployOS-generated and may be rewritten
by DeployOS on redeployment; the custom route must be backed up and
its persistence verified after a fresh deployment. If DeployOS removes
`aicaller-voice.yml`, integrate this rule into its supported persistent
proxy configuration rather than editing `aicaller.yml` repeatedly.

## Configuration and acceptance

Keep `adacertifyexperts.com -> web:8080`, and separately expose
`voice.adacertifyexperts.com -> gateway:3002`. In DeployOS app config:

```dotenv
HOSTED_AI_PROVIDER=openai
HOSTED_AI_API_KEY=<direct OpenAI key stored privately>
VOICE_REALTIME_ENABLED=true
VOICE_GATEWAY_URL=wss://voice.adacertifyexperts.com
```

A change to app environment must be saved and applied to both web and
gateway (a controlled redeploy/restart). Do not put secrets in chat,
GitHub, screenshots or Traefik config. Keep the existing DB URL intact.

```sh
curl -fsS https://voice.adacertifyexperts.com/health
# {"ok":true}
curl -fsS https://adacertifyexperts.com/api/health
# still HTTP 200 from the original web app
docker inspect -f '{{range $name, $_ := .NetworkSettings.Networks}}{{println $name}}{{end}}' aicaller-gateway-1
# aicaller_default and edge
```

A 200 health response verifies DNS/TLS/proxy/gateway reachability but
NOT authenticated WebSocket upgrades or a real inbound call. Verify
bidirectional Telnyx audio, barge-in, booking/recording/transcripts and
actual OpenAI/Telnyx invoice reconciliations under Issue #31 before
general release.
